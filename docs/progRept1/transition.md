you do **not** need the original Python chat thread.

## 2. Environment (NixOS / Nix on WSL, aarch64)

Define the R environment with Nix so it is reproducible and prebuilt from
`cache.nixos.org` where possible. Suggested `flake.nix` (replace/rename the existing one;
keep `flake.lock` committed):

```nix
{
  description = "MATH 448 YouTube engagement project - R environment";
  inputs.nixpkgs.url = "github:NixOS/nixpkgs/nixos-24.11";
  outputs = { self, nixpkgs }:
    let
      system = "aarch64-linux";
      pkgs   = import nixpkgs { inherit system; };
      rWith = pkgs.rWrapper.override {
        packages = with pkgs.rPackages; [
          tidyverse     # dplyr, tidyr, readr, stringr, purrr, tibble, ggplot2, forcats
          lubridate
          jsonlite
          digest        # sha256 verification in download_data.R
          scales
          patchwork     # multi-panel figures
        ];
      };
    in {
      devShells.${system}.default = pkgs.mkShell {
        packages = [ rWith pkgs.typst pkgs.quarto ];
      };
    };
}
```

Run with `nix develop` (or `direnv allow` if you keep `.envrc`). Sanity check:
`Rscript -e 'sessionInfo()'`.

Notes:
- All required CRAN packages exist in `nixpkgs.rPackages` and have aarch64 builds.
  If one is missing/broken, prefer adding another `rPackages.*` entry over
  `install.packages()`; a last resort is `pkgs.rPackages.buildRPackage`.
- Optional: `renv` inside R for CRAN version pinning. On Nix this is usually unnecessary
  and can conflict; skip unless a specific version is required.
- If `NixOS-WSL` has no aarch64 installer, install **Ubuntu ARM64** in WSL and add the
  Nix package manager (multi-user). The flake is distro-independent.

## 3. Repository & VCS strategy

- **Branch layout.** `master` = the R implementation going forward. The Python code and
  its Python dev environment were removed and are preserved intact on the **`legacy-python`**
  branch (a snapshot of the original commit).
- **Consulting the Python reference.** To read the old code without disturbing your
  worktree, use `git show legacy-python:analysis/clean_eda.py`, or add a second worktree:
  `git worktree add ../math448-legacy legacy-python`. Keep `legacy-python` until §10 passes;
  then it can be deleted, or kept as an archive.
- **Where to work.** Develop on `master` directly, or on a short-lived branch
  (`r-transition`) off it if you want to stage the whole port before landing it.
- **Keep the worktree inside the Linux filesystem** (e.g. `~/src/math448`) rather than
  building on `/mnt/d/...`. Nix builds and R I/O on `/mnt` are slow and are a common source
  of permission and CRLF problems. Sync via the git remote (GitHub) or a one-time copy. If
  you must stay on `/mnt/d`, add a `.gitattributes` with `* text=auto eol=lf` and set
  `git config core.autocrlf input`.
- Do **not** commit anything under `data/` (CSVs) or `analysis/output/` — both are
  gitignored. Keep it that way.

## 6. File-by-file translation spec

### 6.1 `analysis/download_data.R`  ← `download_data.py`

Purpose: fetch `datasnaek/youtube-new` and place the `*videos.csv` / `*_category_id.json`
files flat in `data/`, then verify the two US SHA-256 sums.

Requirements:
- Target the same endpoint:
  `https://www.kaggle.com/api/v1/datasets/download/datasnaek/youtube-new`
  (public; no auth needed. If `KAGGLE_USERNAME`/`KAGGLE_KEY` are set, you may add them; the
  base R path can omit auth.)
- Use `download.file(url, dest, mode = "wb", method = "libcurl")` into a
  `tempfile(fileext = ".zip")`, then `unzip(zip, exdir = tmpdir)`.
- Copy only `*.csv` and `*.json` (recursively) into `data/`, flattened.
- Be idempotent: if `data/USvideos.csv` and `data/US_category_id.json` exist and no
  `--force`-style flag is given, skip the download.
- Verify SHA-256 with `digest::digest(f, algo = "sha256")` against:
  - `USvideos.csv` → `09b4eb71295752705e472ebefeac9d2afab4177b7a818af795dea62744a48eb2`
  - `US_category_id.json` → `2e892c5a5e48d284e40fd37de0313912264041aef8833e5323bd2b2fd08c7e25`
- Optional args via `commandArgs`: `--force`, `--dest DIR`, `--from-zip FILE`.

### 6.2 `analysis/profile_data.R`  ← `profile_data.py`

Reproduce the audit and print the same labeled sections to stdout. Use the explicit
`col_types` in §7.1 so parsing is deterministic. Sections (keep the labels/order):
dimensions & columns; dtypes; date ranges; missing/sentinels; duplicates & repeated
snapshots; numeric summary + skew; boolean flags; category distribution (names from
`US_category_id.json`); logical-inconsistency checks; channels & engagement ratios;
per-video dedup preview.

Skewness: Python used the **sample skewness with bias correction (Fisher–Pearson, `g1`)**.
In R: `e1071::skewness(x)` (default `type = 2`) or
`n/((n-1)*(n-2)) * sum(((x-mean)/sd)^3)`. Add `e1071` to the flake, or compute manually to
avoid the dependency. Values to match are in §10.

### 6.3 `analysis/clean_eda.R`  ← `clean_eda.py`

The core. Reproduce, **in this exact order** (order changes the row counts):

1. Read `USvideos.csv` with the §7.1 `col_types`.
2. Parse dates (§7.2).
3. Clean (counts in parentheses must match):
   - drop `video_error_or_removed` rows (→ 40,926)
   - drop fully duplicated rows (`distinct()`) (→ 40,878)
   - drop duplicate `(video_id, trending_date)` pairs, keeping the **last** (→ 40,876)
4. Feature engineering (§7.3).
5. Log transforms, ratios, and the `high_views` label (§7.4).
6. Collapse to one row per video (last trending snapshot) → `data`-level table of
   6,348 rows; write `analysis/output/videos.csv`.
7. Write `analysis/output/summary_*.csv` (same names/contents as Python:
   `summary_cleaning_counts.csv`, `summary_numeric.csv`, `summary_by_category.csv`,
   `summary_by_hour.csv`, `summary_by_dow.csv`) and `cleaning_log.txt`.
8. Draw the eight figures (§8) into `report/figures/` with the **same filenames**.

### 6.4 `analysis/report_numbers.R`  ← `report_numbers.py`

Read `analysis/output/videos.csv` and print the same block of statistics §10 uses
(engagement-ratio describe, correlations with `log_views`, title/tag describes,
`days_to_trend` describe + extremes, zero counts, top categories, raw snapshot stats).
This is the quickest way to eyeball parity.

## 7. Parity rules (get these exactly right)

### 7.1 Reading the CSV
The file has embedded newlines and quotes in `description`, and the `tags` field contains
literal quote characters. `readr::read_csv()` handles quoted fields with embedded
newlines, but supply explicit types so guessing can't drift:

```r
col_types <- cols(
  video_id = col_character(), trending_date = col_character(), title = col_character(),
  channel_title = col_character(), category_id = col_integer(), publish_time = col_character(),
  tags = col_character(), views = col_double(), likes = col_double(), dislikes = col_double(),
  comment_count = col_double(), thumbnail_link = col_character(),
  comments_disabled = col_logical(), ratings_disabled = col_logical(),
  video_error_or_removed = col_logical(), description = col_character()
)
raw <- read_csv("data/USvideos.csv", col_types = col_types)
```
Keep the file in UTF-8 (it has non-ASCII titles). Set `Sys.setlocale("LC_ALL", "C.UTF-8")`
if the NixOS locale is not already UTF-8.

### 7.2 Dates and time
- `trending_date` is **`YY.DD.MM`** (e.g. `17.14.11` = 2017-11-14), **not** `YY.MM.DD`:
  ```r
  trending_date <- as.Date(raw$trending_date, format = "%y.%d.%m")
  ```
- `publish_time` is UTC ISO-8601 with milliseconds:
  ```r
  publish_time <- as.POSIXct(raw$publish_time, format = "%Y-%m-%dT%H:%M:%OS", tz = "UTC")
  ```
- `publish_hour` = UTC hour: `as.integer(format(publish_time, "%H", tz = "UTC"))`.
- `publish_dayofweek` must match Python's `Monday = 0 .. Sunday = 6`:
  ```r
  publish_dayofweek <- lubridate::wday(publish_time, week_start = 1) - 1L
  ```
- `days_to_trend` uses the **UTC date** of `publish_time`:
  ```r
  days_to_trend <- as.integer(trending_date - as.Date(format(publish_time, "%Y-%m-%d", tz = "UTC")))
  ```

### 7.3 Features
```r
title_length     <- nchar(raw$title, type = "chars")
title_word_count <- stringr::str_count(raw$title, "\\S+")
tag_count        <- dplyr::if_else(raw$tags == "[none]" | is.na(raw$tags),
                                   0L, stringr::str_count(raw$tags, stringr::fixed("|")) + 1L)
```
- `[none]` ⇒ **0** tags (this is the sentinel; do not count it as 1).
- Category names from `US_category_id.json` via `jsonlite::fromJSON()`, mapping
  `category_id` → `snippet.title`.

### 7.4 Responses and label
```r
log_views    <- log1p(views); log_likes <- log1p(likes)
log_dislikes <- log1p(dislikes); log_comments <- log1p(comment_count)
like_rate    <- likes / views; comment_rate <- comment_count / views; dislike_rate <- dislikes / views
# label uses the video-level table (see step 6)
high_views   <- as.integer(views >= quantile(views, 0.75))
```
`quantile(..., 0.75)` (R default type 7) matches pandas' linear interpolation, so the
threshold is ~1,473,578 and positives are exactly 25%.

### 7.5 Dedup to one row per video
```r
videos <- snapshots |>
  arrange(video_id, trending_date) |>
  slice_tail(n = 1, by = video_id)   # last trending snapshot per video
```
Equivalent to the Python `sort_values("trending_date").groupby("video_id").tail(1)`.
Result: 6,348 rows.

## 11. Risks and gotchas

- **Day-of-week convention** differs between R and Python (`wday` is Sun=1 by default).
  Use `wday(x, week_start = 1) - 1` to match Monday=0.
- **Skewness definition**: use `e1071::skewness` type 2 (bias-corrected) to match pandas.
- **Date format** `YY.DD.MM` — a single wrong `format=` silently scrambles everything.
- **Timezone**: keep everything UTC; `publish_hour` is UTC, not US-local (a documented
  caveat, not a bug).
- **`[none]` tags** and **`description` NA** are the only "missing data" quirks.
- **This is not a redesign.** Do not "improve" the cleaning, add features, or change
  thresholds during the port — that would invalidate the report's numbers.
- **File I/O on `/mnt/d`** (CRLF, permissions, speed) — prefer the Linux filesystem.
- **The Python reference is the `legacy-python` branch**; it is not in the worktree.
